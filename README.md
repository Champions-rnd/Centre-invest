# HR-аналитика интервью

Стартовый проект для кейса «Сервис HR-аналитики». Целевой сценарий — загрузить WAV и вакансию младшего геймдизайнера, получить расшифровку со спикерами, открыть подтверждающие реплики из отчёта, сверить их с записью и увидеть, что уточнить у кандидата.

## Запуск

Понадобятся Git и Node.js 24 LTS с npm. Из корня репозитория:

```bash
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173> и нажмите **Открыть демоотчёт**. API работает на порту 3001, Vite проксирует запросы `/api`. Демо работает без ключей. В него входят трёхминутная запись из кейса, справочная расшифровка и подготовленный вручную отчёт по четырём критериям. Нажмите на таймкод возле реплики, чтобы перейти к записи. [Атрибуция и лицензия записи](web/public/demo/source-and-license.txt).

Форма нового разбора передаёт WAV, описание вакансии и критерии в API. Интерфейс живого разбора поддерживает редактирование реплик и повторный запрос анализа. Для живой обработки команде предстоит реализовать серверные адаптеры распознавания и анализа.

```bash
npm run check
npm run build
npm start
```

После сборки `npm start` обслуживает сайт и API на <http://127.0.0.1:3001>. Завершите `npm run dev` перед этим запуском. Для адаптеров скопируйте `.env.example` в `.env` и укажите параметры, полученные у оргкомитета. В PowerShell используйте `Copy-Item .env.example .env`.

## Стек

| Часть | Выбор | Причина |
| --- | --- | --- |
| Интерфейс | React, TypeScript, Vite, обычный CSS | Форма и отчёт разрабатываются отдельно, локальный запуск одной командой |
| API | Node.js 24, Express, Multer | Принимает WAV и описание вакансии, координирует распознавание и анализ |
| Контракт | Zod и TypeScript в `shared/contracts.ts` | Браузер и сервер используют одни схемы данных |
| Распознавание | Провайдер с WAV, спикерами и таймкодами. Кандидат — Scribe v3, если доступ подтверждён | Серверный адаптер приводит результат к `Segment[]` |
| Анализ | Серверный вызов текстовой модели через `chatci.online` | Адрес API, протокол, модель и ключ уточняются у организаторов |
| Данные | WAV в памяти на время запроса, результат в браузере | Один сценарий можно показать без БД и регистрации |

Проверьте размер конкурсного WAV в начале. Текущий предел — 50 МБ в форме и API. При необходимости согласуйте изменение лимита с ограничениями модели и памяти, сохранив таймкоды от начала исходной записи. Документация кандидата на STT — [ElevenLabs Scribe](https://elevenlabs.io/docs/overview/models/).

## Кто что меняет

| Участник | Ветка от `dev` | Зона работы |
| --- | --- | --- |
| 1. Ввод и сборка | `feat/intake` | `web/src/intake/`, `web/src/main.tsx`, общая интеграция и настройка PR |
| 2. Расшифровка и отчёт | `feat/report-ui` | `web/src/report/`, `web/src/styles.css`, навигация по аудио и правки текста |
| 3. Распознавание | `feat/stt` | `server/stt/`, живой WAV, спикеры, таймкоды и ошибки провайдера |
| 4. ИИ-анализ | `feat/analysis` | `server/analysis/`, реальный вызов прокси, карта критериев, отчёт |
| 5. Проверка и защита | `feat/qa-demo` | `docs/qa.md`, сверка с записью, сценарий показа и материалы для защиты |

Интегратор согласует изменения `shared/contracts.ts`, `server/index.ts`, `server/report.ts`, зависимостей и `web/src/api.ts`. Если нужен новый формат данных, сначала влейте маленький общий PR в `dev`, затем подтяните его в рабочие ветки. [Контракт API](docs/api.md)

## Ветки и Git

`main` — чистовик и версия для защиты. `dev` — общая ветка сборки. Обе ветки входят в стартовый репозиторий и начинаются с одного коммита. Один участник публикует их в пустой общий репозиторий. Остальные клонируют общий URL.

```bash
git switch dev
git pull --ff-only origin dev
git switch -c feat/stt
# После правок
git add server/stt
git commit -m "Connect WAV transcription"
git push -u origin feat/stt
```

Открывайте PR из `feat/*` в `dev`. Перед слиянием подтяните общую ветку в свою рабочую и проверьте сборку:

```bash
git fetch origin
git merge origin/dev
npm run build
```

Интегратор вливает PR по одному и запускает демо на `dev` после каждого объединения. После общего прогона он открывает PR `dev → main` и объединяет его обычным merge. Для обновления общих веток используйте PR без force-push.

## План на 7 часов

| Время от старта | Что должно получиться |
| --- | --- |
| 0:00–0:30 | Опубликовать ветки, запустить демо у всех, закрепить контракт и получить WAV, вакансию, эталонную расшифровку и параметры ИИ-прокси. |
| 0:30–2:00 | Параллельно улучшать форму и отчёт. Отдельно проверить короткий запуск STT и первый реальный вызов прокси. QA выбирает три фрагмента для сверки. |
| 2:00–3:00 | Влить первые PR. На `dev` получить первую цепочку «WAV → реплики → анализ → отчёт», хотя бы на коротком фрагменте, сохраняя время от начала записи. |
| 3:00–4:30 | Прогнать конкурсное интервью, сверить минимум три цитаты и таймкода, исправить одну ошибку и пересобрать отчёт. Сохранить пример «до/после» в `docs/qa.md`. |
| 4:30–5:45 | Устранить сбои загрузки и прокси, проверить пробелы и вопросы, обновить инструкцию запуска. |
| 5:45–6:30 | Провести репетицию с чистого клона, собрать итоговый `dev` и влить его в `main`. |
| 6:30–7:00 | Резерв на исправление блокирующих ошибок и повторный прогон защиты. |

Доказательность и проверка качества дают 55 баллов. На защите покажите переход от цитаты к месту в аудио, критерий без данных и изменение отчёта после исправления реплики. Добавьте подтверждённые сведения об аудио и атрибуцию, указанную в кейсе, если включаете запись или фрагменты в демонстрационные материалы.

Если у команды пока нет рабочего STT, эталонную расшифровку можно использовать для проверки живого анализа через прокси, отдельно помечая источник текста. Когда STT заработает, повторите сценарий от WAV. Формат доступа к ИИ-прокси и данные интервью в PDF не приложены.
